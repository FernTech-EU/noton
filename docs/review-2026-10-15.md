## Open review findings

### P1 — Backup retention can delete another library's backups

`crates/teksilo_ui/src/session_vm.rs:949–961` selects retention candidates by
filename stem alone. Two different libraries, such as `one/Notes.noton` and
`two/Notes.noton`, using the same configured backup directory share that candidate
set. With `backup_keep = 1`, backing up the second library deletes the first
library's only backup. This was reproduced with disposable libraries and isolated
preferences through the production MCP interface; no user libraries were used.
Scope backup names/retention to the library UUID, or verify the stored UUID before
deleting a candidate. Existing backups need a compatible migration strategy.
Evidence: `target/audit-2026-10-15/backup-review.log`.

### P2 — Creating a library with a bare relative filename fails

`crates/noton_format/src/lib.rs:241–243` falls back to `.` only when `parent()`
is `None`. For `Notes.noton`, Rust returns an empty parent path, and canonicalizing
that path fails. Reproduced from `/tmp` with:

```sh
/home/cyril/Devel/noton/target/debug/noton --mcp --library noton-review-relative.noton </dev/null
```

The application reports `No such file or directory (os error 2)` instead of
creating the library. Treat an empty parent as `.` before canonicalizing.

### Open acceptance failure — Headless table geometry after reopen

`tools/mcp_table_accessibility.py` still fails at the reopened-canvas assertion:
an accessible Cell has no bounds. Initial editing and projection checks pass.
This reproduces the historical failure, so it is not evidence of a newly introduced
0.18 regression. The native visual script passes all nine cell-bound checks in
both projections after reopen. Native screen-reader behavior remains unverified.
Evidence: `target/audit-2026-10-15/table.log` and the native visual captures.

These findings are reported, not fixed by the dependency update.

## First ergonomics pass — 15 October 2026

Implemented the first writing, editing, navigation and search improvements:

- **Start a note** and Ctrl+N create the missing folder if necessary, create a note
  with a text block, and focus it. Empty notes offer **Start writing**. Double-click
  blank canvas space to create and focus text at that scene position.
- Typing hides canvas resize handles, the redundant block type header and the
  Editing badge. Formatting remains available; Escape returns to block controls.
- A labeled **Navigation** button and Ctrl+Shift+backslash toggle the side panes.
  Narrow windows use the same button to return to navigation. F6 skips hidden panes.
- Search keeps the current note open while typing. Results include accent-aware
  excerpts, occurrence counts and folder context, with measured row heights.
  Activating a text match focuses and selects its first occurrence. Clearing the
  query or pressing Escape in search restores the prior note, projection and
  navigation visibility. Block labels, descriptions and image alt text remain
  searchable without treating their offsets as document offsets.

Added Unicode-offset and view-model regressions, plus `tools/mcp_ergonomics.py`:
its six native scenarios cover immediate writing at desktop/narrow sizes, the
navigation toggle, blank-canvas writing, an empty note, and multiline Unicode
search. Selection is verified by replacing the first match through keyboard
input and undoing it, not merely checking whether an editor appears.

Final verification: 174 workspace tests and 22 mock tests passed, with the same
three ignored doctests. All-target build, strict real/mock Clippy, documentation,
formatting, whitespace and locale parity (218 keys) passed. The production binary
was restored after mock checks.

Smoke and all 17 existing stories passed. All six new native scenarios passed.
Native visual automation passed at 1280×850 and 600×700, including reopened table
geometry, with 19 captures. Native idle/autosave passed with zero reported frames

Selected writing, narrow layout, navigation-hidden, blank-canvas and search
captures were visually inspected. The pre-existing headless reopened-table Cell
